# MR 书法 5.16 版本功能审计与真实化开发文档

审计日期：2026-06-11  
基线版本：已恢复到 2026-05-16 的项目树，当前恢复提交为 `fd2f60e 恢复到5月16日版本`。  
运行方式：静态网页项目，当前可通过本地服务器访问，例如 `http://localhost:41496/`。

## 1. 当前结论

5.16 版本不是完全没有后台，它的后台入口仍然存在：

- `main-admin.html`：主场景管理页，用于编辑主场景里的模型、装饰物、导入模型和灯光。
- `realistic-admin.html`：写实 3D 样张管理页，用于编辑写实桌面样张里的对象。
- `index.html`：前台 MR 书法学习演示页，包含 10 步学习路径、热点、模拟操作和场景编辑面板。
- `realistic-demo.html`：写实 3D 样张展示页。

真正的问题是：后台编辑能力和前台学习产品能力还没有完全形成闭环。后台部分已有一些真实能力，但主要保存到浏览器本机；前台已开始接入本机学习状态，但“真实书写、评分算法、作品截图、视频生成、图文报告”等核心能力仍未完成。

因此下一阶段的目标不应该是继续堆 Demo 页面，而是把每个可点击控件真实化：能改变状态、能保存、能读取、能失败提示、能被验收。

### 2.3 明显缺失

- 没有真实用户练习输入：缺少书写画布、笔迹采样、压感/速度模拟、撤销重写。
- 没有真实评分算法：结构、笔画、笔法、力度、流畅度都还是预设分。
- 任务系统仍较薄：当前字、碑帖和模式已有可写状态，但还没有完整字帖库、任务列表和完成规则。
- 缺少完整学习记录页：练习次数、作品数量已有本机来源，但还没有记录列表、趋势图、筛选和详情。
- 没有项目级导入导出：后台保存依赖 localStorage/IndexedDB，不能作为团队长期开发资产流转。
- 没有统一配置层：主场景、写实场景、前台学习流程各自保存，缺少统一 schema 和版本迁移。
- 没有权限/发布边界：后台页面没有保护，也没有“预览 / 发布 / 回滚”的概念。
- 没有系统化测试：目前只能靠人工访问页面，缺少 smoke test、交互验收和数据迁移验证。

## 3. 前端假控件真实化原则

后续开发时，每个按钮都必须满足下面至少一种状态：

1. **真实可用**：点击后会修改明确的数据状态，刷新后仍能读取，并有成功/失败提示。
2. **明确禁用**：功能尚未开发时禁用按钮，并写清楚原因，例如“练习画布接入后可用”。
3. **明确演示**：若必须保留演示能力，按钮文案和 UI 标识必须写成“演示播放”或“演示报告”，不能伪装成真实保存/导出。

任何新功能都要同时补齐四件事：

- 状态模型：这个操作写入什么数据。
- UI 反馈：成功、失败、空状态、加载态怎么展示。
- 持久化：刷新页面后是否保留，数据放在哪里。
- 验收标准：如何确认它不是只改了文案。

## 4. 建议的数据模型

短期仍保持纯静态项目，但先把数据结构整理清楚。推荐新增 `state/` 或 `src/state/` 层，统一封装 localStorage/IndexedDB。

### 4.1 ProjectConfig

用于保存项目级配置。

- `version`：schema 版本。
- `activeScene`：当前主场景或写实场景。
- `roomTextures`：六面贴图路径。
- `roles`：场景角色列表。
- `mainSceneLayout`：主场景物体布局、灯光、导入模型索引。
- `realisticSceneLayout`：写实场景物体布局、导入模型索引。

### 4.2 LearningTask

用于替代 `SCENES` 里硬编码的学习任务。

- `id`
- `mode`：`single`、`phrase`、`creation`
- `glyph`
- `copybook`
- `strokePlan`
- `requiredSteps`
- `status`

### 4.3 PracticeSession

用于保存一次练习。

- `id`
- `taskId`
- `startedAt`
- `endedAt`
- `strokes`
- `metrics`
- `score`
- `feedback`

### 4.4 ArtworkRecord

用于保存作品。

- `id`
- `sessionId`
- `title`
- `style`
- `imageData` 或截图引用
- `score`
- `createdAt`

### 4.5 ReportRecord

用于导出学习报告。

- `id`
- `range`
- `summary`
- `weaknesses`
- `recommendations`
- `exportedAt`

## 5. 分阶段开发路线

### 阶段 A：控件盘点和演示态治理

目标：把“假的”先标清楚，避免用户误以为可用。

任务：

- 建立控件清单，覆盖 `index.html`、`main-admin.html`、`realistic-admin.html`。
- 给每个按钮标记 `data-feature-state="real|demo|disabled"`。
- 对未实现按钮加禁用态或演示态标识。
- 模式 tabs 接入真实 active state，至少能切换“单字学习 / 集字练习 / 创作”的内容范围。
- 将 `SCENES.actions.response` 里的“已保存、已导出、已生成”等假结果改成真实执行或明确演示。

验收：

- 页面上不存在“看起来保存了但实际没有数据”的按钮。
- 刷新页面后，真实按钮产生的数据仍可读取。
- 未完成按钮点击不会给出虚假的成功反馈。

### 阶段 B：统一本机状态层

目标：先不引入后端，也要有一套可靠的本机数据层。

任务：

- 新增统一 storage 模块，集中管理 localStorage、IndexedDB、schema version 和迁移。
- 把主场景 `mr-calligraphy-main-scene-layout-v1`、写实场景 `mr-calligraphy-realistic-layout-v1`、房间配置 `mr-calligraphy-room-config-v3-wood` 纳入统一读写。
- 新增项目导出 JSON：导出场景配置、学习记录、作品索引，不直接导出大模型二进制。
- 新增项目导入 JSON：校验版本、预览差异、确认后覆盖。
- 给后台保存动作增加“上次保存时间”和“保存失败”提示。

验收：

- 在一个浏览器里编辑主场景，刷新前台后能看到结果。
- 导出 JSON 后清空 localStorage，再导入 JSON 能恢复配置。
- schema 版本不匹配时有清晰提示，不静默失败。

### 阶段 C：前台学习流程真实化

目标：让前台从“剧本展示”变成“可完成一次学习任务”。

任务：

- 今日字选择写入 `LearningTask`，学习路径根据 task status 更新。
- “进入临摹训练”创建 `PracticeSession`。
- “播放讲解”拥有播放状态：未播放、播放中、已完成。
- “示范模式 / 对比模式”切换真实训练模式，并影响画布显示。
- “保存作品”创建 `ArtworkRecord`，能在作品/复盘页读取。
- “导出学习报告”生成 JSON 或 HTML 文件下载，数据来自真实 session 和 artwork。

验收：

- 从首页开始可以完成一次“选择字 -> 讲解 -> 临摹 -> 保存作品 -> 查看报告”的闭环。
- 报告里的分数、练习次数、作品数量来自当前数据，而不是静态文案。
- 页面刷新后仍能继续查看刚才的记录。

### 阶段 D：书写练习和评分

目标：补上 MR 书法产品的核心真实交互。

任务：

- 新增书写画布，支持鼠标/触控采样。
- 记录每笔的点位、时间、速度和笔画顺序。
- 建立“永”字基础范字路径，可先用 SVG path 或 JSON 点位。
- 实现第一版评分：
  - 结构：整体 bounding box、重心、比例。
  - 笔画：起止点、方向、长度。
  - 流畅度：速度变化和中断次数。
  - 完成度：笔画数量和顺序。
- 支持重写、撤销、回放。

验收：

- 用户写两次不同质量的字，评分结果会有可解释差异。
- 评分报告能指出至少 3 个具体问题。
- 书写轨迹可回放，并能保存到 `PracticeSession`。

### 阶段 E：后台编辑器产品化

目标：把当前后台从“单机调参页”升级成长期开发可用的场景编辑器。

任务：

- 主后台增加对象列表/图层面板，支持搜索、隐藏、锁定、分组。
- 补齐自定义几何体 UI：代码里已有 custom object 逻辑，但 5.16 页面没有对应入口。
- 导入模型增加校验：尺寸、中心点、文件类型、加载失败、重复导入。
- 增加项目级“导入/导出/备份/恢复”。
- 增加保存历史，至少保留最近 10 次布局快照。
- 后台页面增加“预览前台”入口，能带当前配置打开 `index.html`。
- 明确主后台与写实后台的边界，避免两套编辑器能力割裂。

验收：

- 非开发人员可以通过后台完成一次物体导入、摆放、保存、预览、回滚。
- 删除导入模型后，布局索引和 IndexedDB 数据不会出现悬挂引用。
- 自定义几何体能从 UI 新增、编辑、删除、撤销。

### 阶段 F：测试和发布标准

目标：每次提交都能证明功能可用。

任务：

- 增加静态语法检查命令，覆盖 `script.js`、`main-admin-scene.js`、`realistic-scene.js`。
- 增加页面可访问 smoke test：`/`、`/main-admin.html`、`/realistic-demo.html`、`/realistic-admin.html`。
- 增加浏览器手工验收清单。
- 后续如引入 Playwright，优先覆盖：
  - 主场景加载不白屏。
  - 主后台选择对象、改坐标、刷新保留。
  - 前台保存作品后复盘页可读取。
  - 导出报告会下载文件。

验收：

- 每个功能提交必须更新本文档或对应开发记录。
- 每个新增真实按钮必须有至少一条验收步骤。
- 不允许用“已模拟完成”冒充真实完成。

## 6. 优先级建议

- 标记或禁用假控件。
- 修正所有虚假成功文案。
- 给后台入口加明显导航：前台可以进入 `main-admin.html`，主后台可回到前台。
- 写清楚本地数据保存位置和清空风险。

### P1：做出真实闭环

- 模式 tabs 真实切换。
- 今日字、练习会话、保存作品、学习记录、导出报告全部接入本机状态。
- 先用 JSON/HTML 导出报告，不急于做 PDF。

### P2：核心练习能力

- 书写画布。
- 轨迹保存。
- 初版评分。
- 回放和复盘。

### P3：后台产品化

- 对象图层面板。
- 项目导入导出。
- 版本历史。
- 自定义几何体 UI。

## 8. 开发纪律

- 每次开发只做一个可验收功能，避免再出现多个 demo 堆叠但不可用。
- 每次提交信息使用中文，说明真实完成的能力。
- 每次提交都更新开发文档，记录：
  - 功能名
  - 涉及文件
  - 验收方式
  - 已知限制
- 任何“演示态”都必须在 UI 和文档中明确，不允许伪装成生产功能。
- 后台保存必须说明保存范围：本机浏览器、项目 JSON、还是远端服务。

## 9. 当前最需要完善的功能判断

我认为最不完善的不是 3D 场景，而是学习业务闭环：

1. 前台缺少真实练习输入，所以评分、报告、历史记录都没有事实来源。
2. 保存/导出/生成类按钮没有真实产物，用户会很快发现不可用。
3. 后台编辑保存只在本机浏览器，长期开发协作很难复现同一场景。
4. 主后台和写实后台是两套编辑器，缺少统一项目配置。
5. 缺少“这个功能是演示还是可用”的明确边界，导致体验上像半成品。

下一步建议先做 P0 和 P1：把假控件治理掉，并完成“选择字 -> 开始练习 -> 保存作品 -> 查看记录 -> 导出报告”的最小真实闭环。这样这个项目才会从“漂亮演示”变成“真实可用的书法学习原型”。
