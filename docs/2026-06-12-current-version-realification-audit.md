## 2. 这一版最不完善的地方

### 2.1 本机真实和生产真实混在一起

当前很多按钮确实能用，但它们主要写入本机浏览器。例如学习状态、作品、计划、档案、报告批注、后台布局、发布版本和远端配置，大多保存在 `localStorage` / `IndexedDB`。

用户看到“发布”“同步”“教师批注”“AI 讲解”“报告”“分享”这些词，会自然理解成云端、账号、权限和跨设备能力。当前版本还没有这些生产闭环，因此 UI 必须持续强调“本机”“导出”“远端 API adapter”，不能让用户误会已经上线。

### 2.2 前台学习路径仍有静态剧本残留

前台已经能从真实练习、作品、报告和计划状态读取一部分指标，但步骤标题、热点说明、部分学习动作仍依赖 `SCENES` 和静态导览配置。它现在像“真实状态 + 导览剧本”的混合体，还不是完整课程引擎。

需要继续把 10 步路径改成由 `LearningTask`、`PracticeSession`、`ArtworkRecord`、`ReportRecord` 和 `PlanRecord` 推导内容、完成条件、下一步动作和锁定状态。

### 2.3 AI 讲解只是本机语音，不是 AI 服务

当前讲解能力调用浏览器 `speechSynthesis` 朗读本机讲解文本。这是可用的本机语音功能，但不是云端 AI 音频，也不是根据学生真实笔迹生成的动态反馈。

真实化方向：

- UI 文案保留“本机语音讲解”边界。
- 新增 `LectureService` adapter，支持 `local-tts`、`remote-ai-audio`、`remote-ai-text` 三种来源。
- 把讲解生成结果写入报告和学习记录，避免只在界面临时播放。

### 2.4 评分仍是启发式，不是专业书法识别模型

当前评分已经会读取真实笔迹点位，并输出结构、笔画、笔法、力度、流畅度等基础评分证据。但它仍是浏览器端启发式算法，不是训练模型，也没有范字路径库、笔顺模型、压感校准和教师评分标定。

真实化方向：

- 增加范字路径库和笔顺数据。
- 保存设备、压力、采样率和画布尺寸。
- 增加评分版本号和评分证据说明。
- 预留 `ScoringService`，未来接服务端模型。

### 2.5 报告和教师批注还停留在本机

HTML 报告、原生 PDF、报告对比、多报告趋势和本机教师批注已经可用，刷新后也能复现。但教师批注只是当前浏览器里的报告字段，不代表账号化教师端，也没有签名验真、服务端审计和长期归档。

真实化方向：

- 固定 `ReportRecord` schema 和版本迁移。
- 新增账号化 `ReportRepository`。
- 教师批注增加 reviewerId、role、签名、审计记录和服务端时间。
- PDF 增加作品截图嵌入、图表增强和验真标记。

### 2.6 分享能力只是导出文件

当前作品分享页和报告分享主要是离线 HTML / PDF / WebM 文件导出，属于真实文件产物，但不是公开链接、课堂发布、社群分享或微信分享。

真实化方向：

- 保持现有按钮为 `real-export`。
- 新增 `ShareService`，支持生成公开链接、撤回公开链接、访问权限和过期时间。
- 分享记录写入 `ShareRecord`，并在档案里可追溯。

### 2.7 后台还不是可协作的项目后台

主后台和写实后台都能编辑本机场景，也能导出项目档案、做本机发布、回滚、远端发布包预检和回执审计。但它们不是账号后台，任何能打开页面的人都能改当前浏览器里的数据。

真实化方向：

- 统一主后台和写实后台对象 schema。
- 把本机项目档案升级为 `ProjectRepository`。
- 接入账号、角色、权限、审计和发布审批。
- 远端发布由“用户配置 endpoint”升级为“生产发布服务”。

### 2.8 远端 API adapter 有了，但服务端产品没有

计划仓库、学习档案仓库和后台远端发布都已有 API 合同、mock server、endpoint/token 配置、GET/PUT/POST 检查和本机状态持久化。这个方向是对的，但它目前证明的是“前端能对接 API”，不是“项目已有生产后端”。

真实化方向：

- 补生产服务端仓库。
- 补登录态和 token 刷新。
- 补服务端分页、冲突合并、签名回执和不可篡改审计。
- mock server 保留为本地开发验收，不再作为产品能力宣传。

### 2.9 浏览器级验收还不够

现在 smoke test 很强，能检查语法、页面、状态层、mock server 和很多数据函数。Playwright 也已有第一批用例，但测试覆盖还不足以证明所有复杂 UI 都真实可用，尤其是导入模型、PDF 下载、教师批注、远端接口失败、移动端布局和 WebGL 非空渲染。

真实化方向：

- 扩展 Playwright 覆盖报告教师批注、学习档案同步、计划冲突处理、项目档案恢复和远端发布回执。
- 给 WebGL canvas 加非空像素检查。
- 下载类功能校验文件名、MIME 和关键内容。
- 移动端视口检查后台面板不重叠。

## 4. “假界面”真实化标准

一个前端入口只有同时满足以下条件，才能继续标记为真实能力：

| 条件 | 要求 |
| --- | --- |
| 数据来源 | 明确读取 state、storage key、IndexedDB、文件或 API |
| 执行动作 | 明确调用函数、写入字段、生成文件或发起请求 |
| 成功反馈 | 页面状态、文件下载、版本号、记录数或回执发生可见变化 |
| 失败反馈 | 未配置、无数据、权限不足、浏览器不支持、网络失败时有明确提示 |
| 持久化 | 刷新、切页、重新打开或重新导入后能复现 |
| 自动验收 | 至少有 smoke、数据层脚本或 Playwright 覆盖核心路径 |
| 边界说明 | 本机、导出、远端 adapter、生产云端必须分清楚 |

不能再出现的情况：

- 点击后只显示“成功”，但没有数据写入或文件产物。
- 文案写“发布/同步/分享”，实际只是本机状态，却没有边界说明。
- mock server 能跑，就把功能说成已经有生产服务。
- 按钮可点击，但失败时只有控制台错误。

## 5. 建议真实化路线

### P0：把高预期功能的边界写清楚

交付：

- 所有“AI、评分、同步、发布、分享、教师批注、后台”文案增加本机/导出/远端 adapter 边界。
- 远端未配置时，检查/推送按钮保留明确禁用或状态提示。
- README 和页面状态区都说明：当前静态项目无账号后端。

验收：

```bash
node scripts/control-inventory.js --check
node scripts/smoke-test.js --base-url=http://localhost:41496/
```

### P1：补浏览器级真实交互测试

交付：

- Playwright 覆盖报告教师批注保存、刷新复现、清除批注。第一版已补入 `tests/e2e/real-flows.spec.js`。
- 覆盖学习档案远端同步成功和失败。
- 覆盖计划冲突解决三种策略。
- 覆盖主后台远端发布回执导出。
- 覆盖 WebGL canvas 非空像素。

验收：

```bash
npm run test:e2e
```

### P1：把课程路径改成任务驱动

交付：

- `SCENES` 只保留视觉场景配置。
- 学习任务、步骤完成条件、下一步动作由 `LearningTask` 和状态层推导。
- 静态热点说明接入真实任务、练习、作品、报告和计划状态。

验收：

- 清空本机状态后，不显示伪造完成度。
- 完成一次练习、保存作品、生成报告后，步骤完成状态真实变化。

### P2：补账号化 repository

交付：

- `PlanRepository`、`HistoryRepository`、`ReportRepository`、`ProjectRepository` 服务端草案和最小实现。
- 登录态、用户 ID、角色、token 刷新和服务端分页。
- 冲突解决从计划级扩展到字段级。

验收：

- 两个浏览器或两台设备能读取同一账号数据。
- 断网、token 过期、远端冲突时都有可恢复状态。

### P2：升级评分和讲解服务

交付：

- `ScoringService` adapter。
- `LectureService` adapter。
- 范字路径库、笔顺库、压感字段和评分版本。
- 本机 fallback 与服务端结果可并存。

验收：

- 同一笔迹可重复得到同一评分版本结果。
- 服务端不可用时仍保留本机基础评分。
- 报告能显示评分来源、版本和证据。

### P3：后台项目化和生产发布

交付：

- 统一主后台/写实后台对象 schema。
- 项目仓库支持远端保存、版本历史、字段合并、资产签名。
- 远端发布服务支持审批、发布锁、CDN 回执和不可篡改审计。

验收：

- 项目档案可跨浏览器恢复。
- 服务端能拒绝摘要不一致、权限不足和重复发布。
- 发布回执可以在本机和服务端双向核对。

## 6. 下一个开发批次建议

我建议下一批不要先做新页面，而是按下面顺序推进：

1. 扩展 Playwright：先把报告教师批注、远端回执、计划冲突和学习档案同步跑成浏览器级用例。
2. 清理高预期文案：把“本机真实”和“生产真实”的边界放到页面状态区。
3. 任务驱动化：把 `SCENES` 里的学习说明逐步迁移到 `LearningTask` 和状态层。
4. 账号化 repository 设计：先写服务端合同和最小 mock，再接真实服务。
5. 后台 schema 统一：减少主后台和写实后台长期分叉。
