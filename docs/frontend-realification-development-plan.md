# 前端操作界面真实化开发文档

日期：2026-06-11  
适用版本：5.16 恢复线后的当前 `main` 分支  
当前本地入口：`http://localhost:41496/`、`http://localhost:41496/main-admin.html`、`http://localhost:41496/realistic-admin.html`

补充文档：针对当前用户反馈“很多前端操作界面只是假的、用不了”的专项审计和真实化路线，见 `docs/current-version-gap-and-realification-plan.md`。

## 1. 结论

当前版本已经不再是完全静态 Demo：前台已有本机学习状态、书写画布、作品保存、HTML 报告、WebM 回放、学习档案、回收站和任务进度；主后台和写实后台已有对象编辑、模型导入、项目档案、草稿预览、本机发布版本列表和回滚。

但它仍然不是完整可交付产品。最大问题是：很多界面虽然能点击，也被标成 `real`，但真实程度主要停留在“本机可用”。用户期待的云端课程、专业评分、社交分享、账号权限、多人协作、稳定发布和浏览器级测试还没有完成。

因此后续真实化不能只看按钮是否有 handler，而要看它是否满足四个条件：

- 有真实数据来源。
- 点击后产生可验证的状态变化或文件产物。
- 刷新、切页、导出、恢复后仍能复现。
- 失败、空状态和未接入能力不会伪装成成功。

## 3. 当前最像“假的”的界面来源

1. `SCENES` 里的部分标题和热点说明仍是静态叙事；第一批固定成绩已改为本机状态或中性占位，笔画拆解、创作实践和复习巩固动作已写入本机阶段记录，写实样张入口、相机控件和前台动态热点按钮也已改为真实本机控件，但后续还要继续减少热点内容的静态叙事比例。
2. `data-feature-state` 已开始拆成本机真实、文件导出、本机发布和演示内容，控件清单已覆盖静态 HTML 和前台动态控件；后续新增控件仍要持续审计，不能回到“一律真实可用”的粗粒度标注。
3. 主后台“发布到前台”和写实后台“发布到演示”已能记录本机发布版本和回滚版本，但用户仍可能理解成线上发布。
4. AI 讲解、评分、分享这些高预期功能目前是本机原型能力，需要在 UI 和文档中降低误解。
5. Smoke test 已覆盖语法、控件清单、档案迁移、资产哈希、项目 Schema 和页面可访问，但仍不等于真实浏览器内交互闭环。

## 4. 真实化状态分级规范

控件状态已从早期的 `real|demo|disabled` 细化为下面几类。短期继续兼容旧值，但新控件应使用更明确的状态。

| 状态 | 含义 | 示例 |
| --- | --- | --- |
| `real-local` | 本机真实可用，刷新可保留，但不跨设备 | 保存作品、学习档案、后台草稿 |
| `real-export` | 会产生真实文件产物 | 导出 HTML 报告、导出项目档案、导出 WebM |
| `real-published-local` | 发布到本机前台或演示快照 | 主后台发布到前台、写实后台发布到演示 |
| `demo-content` | 内容是演示素材，可点击但不应伪装成真实数据 | 静态热点、样张展示、固定学习指标 |
| `disabled` | 功能尚未接入，不允许成功反馈 | 云端分享、TTS、多人协作 |

每个状态都要在 UI 提示里讲清楚保存范围，例如“本机保存”“导出文件”“本机发布快照”“演示内容”。

## 5. 控件真实化开发规则

新增或改造控件时必须补齐以下字段：

- 控件 id 或选择器。
- 状态等级：`real-local`、`real-export`、`demo-content` 或 `disabled`。
- 数据来源：读取哪个 state、storage key、IndexedDB store 或文件。
- 执行动作：调用哪个函数，写入什么字段。
- 成功反馈：成功后 UI 哪一块会变化。
- 失败反馈：缺少笔迹、缺少报告、导入失败、浏览器不支持时怎么提示。
- 验收步骤：手工如何证明刷新后仍然有效。
- 测试覆盖：至少 smoke test；高风险功能补 Playwright。

禁止继续新增只返回静态成功文案的按钮。

## 6. 分阶段真实化路线

### 阶段 1：控件状态再审计

目标：把“本机真实”和“生产真实”分开。

任务：

- 扩展 `scripts/control-inventory.js`，支持新状态值。第一版已完成。
- 将前台、主后台、写实后台所有按钮从粗粒度 `real` 迁移到更明确的状态。第一版已完成。
- 对 AI 讲解、发布、分享、报告、视频导出等高误解控件增加状态说明。第一版已完成。
- 对所有未知动作保持禁用，避免静态文案伪成功。

验收：

- 运行控件清单时，能看到 `real-local`、`real-export`、`demo-content`、`disabled` 的数量。
- 页面上用户可以直接看出功能是本机保存、文件导出还是演示内容。
- 未接入云端/分享/TTS 的按钮不会显示成功。

### 阶段 2：把静态场景数据改成真实学习数据

目标：前台学习界面不再主要依赖 `SCENES` 静态指标。

任务：

- 首页指标读取 `MRAppState.getStats()` 和任务进度。第一版已完成。
- 学习路径完成状态读取真实练习、作品和报告。第一版已完成，并已区分空练习会话和真实笔迹练习。
- 学习步骤路由：步骤导航、快速上一步/下一步和键盘切换写入 `?step=1-10`，刷新和浏览器返回可恢复当前步骤。第一版已完成。
- 学习热点路由：点击热点会写入 `point=1-3`，`?step=4&point=2` 可直达指定步骤的指定热点，刷新和浏览器返回可恢复。第一版已完成。
- “查看笔画分析”读取当前练习或最近作品的真实评分维度。第一版已完成，已显示结构化详情和空状态。
- “查看笔画分析”显示基础练习评分证据，包括目标笔画、采样点、覆盖、重心偏移、停顿、压感和五项维度理由。第一版已完成。
- “查看成就”改成由真实里程碑推导，未达成时显示明确空状态。第一版已完成，已按本机练习、作品、报告、评分和计划计算。
- “进入笔画拆解 / 进入创作 / 复习巩固”写入本机学习阶段记录，并进入任务进度里程碑。第一版已完成。
- 任务依赖和完成条件：任务库新增 `dependsOn` 和 `completionRules`，按阶段、练习、作品、报告和可选均分推导完成状态，未完成前置时锁定后续任务并阻止选择。第一版已完成。

验收：

- 清空本机学习状态后，前台不应显示 24.5 小时、256 字这类静态成绩。
- 新写一次练习并保存作品后，首页和路径状态会随之变化。
- 访问 `/?step=3` 应直接打开第 3 步；点击快速上一步/下一步后 URL 中的 `step` 应同步变化，浏览器返回应恢复前一个步骤。
- 访问 `/?step=4&point=2` 应直接打开第 4 步第 2 个热点；点击其他热点后 URL 中的 `point` 应同步变化，浏览器返回应恢复上一个热点。
- 没有真实笔迹时，笔画分析显示“先完成一次练习”，不返回假分析。
- 有真实笔迹时，笔画分析和作品复盘应显示基础练习评分依据；刷新后仍能读取已保存的评分证据。
- 点击笔画拆解、创作实践和复习巩固动作后，任务面板应增加阶段记录，刷新后仍可读取。
- 未完成基础任务时，后续任务卡应显示未解锁和前置原因；完成基础任务的阶段、练习、作品和报告后，下一任务应解锁，刷新后仍能复现。

### 阶段 3：补强学习档案和报告

目标：让复盘能力更像真实学习产品。

任务：

- 增加结构、笔画、笔法、力度、流畅度的长期趋势曲线。第一版已完成。
- 增加独立历史详情路由，可直接打开某条练习、作品或报告。第一版已完成，支持 `?history=记录ID` 和复制直达链接。
- 报告详情页站内展示，HTML 下载作为导出能力。第一版已完成，支持 `?report=报告ID`、复制报告链接和从历史报告跳转。
- 报告字段级交互图表、签名水印和站内“打印 / 保存 PDF”入口。第一版已完成，支持按结构、笔画、笔法、流畅、力度切换趋势。
- 报告跨版本对比：同一浏览器本机生成过的相邻两份报告可比较平均分、练习数、作品数、学习分钟和字段级能力变化。第一版已完成。
- 报告对比导出：相邻两份本机报告可导出离线 HTML 对比页，并在浏览器中打印或保存为 PDF。第一版已完成。
- 多报告趋势图：同一浏览器本机生成过的多份报告可显示平均分和当前字段趋势线。第一版已完成。
- 报告字段多选：多报告趋势图可同时叠加多个能力字段线，并保留报告序列跳转。第一版已完成。
- 报告趋势自定义悬浮提示：多报告趋势线、报告点位和字段按钮可显示来自本机报告序列的标题、分数、练习数、作品数和字段变化。第一版已完成。
- 报告趋势提示固定与复制：多报告趋势提示层可固定当前提示，并把标题和详情复制到剪贴板。第一版已完成。
- 报告趋势缩放：多报告趋势可在最近 8 份本机报告内放大、缩小和重置，图线、字段差值和点位卡片都会按当前视图重算。第一版已完成。
- 报告趋势逐点明细：多报告趋势可展开某一份报告，查看统计、字段分数和相对前一份可见报告的变化，并保留打开报告入口。第一版已完成。
- 报告趋势字段分组模板：多报告趋势可一键切换字形、笔势、节奏和全部字段组合，字段线、差值和图例会同步重算。第一版已完成。
- 增加作品对比：同一字不同日期的笔迹、评分和截图对照。第一版已完成，学习档案会自动对比最近两幅同字作品。
- 增加作品集：作品搜索、标签筛选、标签编辑和作品直达路由。第一版已完成，支持 `?artwork=作品ID` 并复用学习档案详情。
- 增加作品分享页导出：最近作品可生成离线 HTML 分享页。第一版已完成，包含作品截图、评分、标签、反馈、来源说明和打印入口。
- 增加学习计划提醒与复盘触发：计划项支持到期、提醒、顺延、复盘动作和复盘完成状态。第一版已完成。

验收：

- 选择任一历史记录能复制链接或通过详情路由重新打开。
- 至少两个日期的练习能生成维度级趋势。
- 报告页面内容全部来自本机记录，不依赖静态模板分数。
- 点击站内报告任一能力字段，趋势图和说明应切换到对应字段；下载 HTML 报告应包含本机报告水印。
- 至少生成两份本机报告后，站内报告应显示上一份和当前报告的差值，并可跳转查看对应报告；只有一份报告时必须显示不可对比空状态。
- 至少生成两份本机报告后，点击“导出对比页”应下载可离线打开的 HTML 文件，页面应包含两份报告 ID、统计差值、字段差值和本机导出边界说明。
- 至少生成两份本机报告后，多报告趋势应显示报告序列、平均分线和当前能力字段线；点击报告序列点应打开对应站内报告。
- 在多报告趋势里选择多个能力字段后，图表应同时显示多条字段线；至少保留一个字段被选中，不能退回空图。
- 悬停或键盘聚焦多报告趋势线、报告点位和字段按钮时，应显示站内自定义提示；提示内容来自当前本机报告序列，不应出现静态假数据，打印报告时应隐藏该提示层。
- 在趋势提示层点击“固定”后，移动鼠标不应关闭当前提示；点击“复制”应复制当前提示标题和详情，并给出成功或失败反馈。
- 在多报告趋势中点击“放大 / 缩小 / 重置”后，当前可见报告数量、趋势图、字段差值和报告点位应同步变化，并且不会生成不存在的报告数据。
- 在多报告趋势中点击任一点位的“明细”后，应在当前图表下展开这份报告的统计和五项字段变化；点击“报告”仍应打开对应站内报告。
- 点击“字形 / 笔势 / 节奏 / 全部”字段模板后，多报告趋势应切换到对应字段组合，并保持至少一个字段被选中。
- 同一个字保存至少两幅作品后，学习档案应显示作品对比，包含前后截图、评分差、笔画差、采样差和可打开详情的入口。
- 保存作品后，学习档案里的作品集应能按标题、字、风格或标签搜索；编辑标签后刷新仍应保留，并能通过 `?artwork=作品ID` 打开这幅作品。
- 保存作品后，点击“导出分享页”应下载可离线打开的 HTML 文件；没有作品时按钮应禁用或返回明确空状态，不能提示已分享成功。
- 生成学习计划后，每个计划项应显示到期、提醒和复盘目标；点击“顺延”会改写本机到期/提醒时间，点击“复盘”会写入复盘完成时间并触发下一步学习入口。

### 阶段 4：后台项目化

目标：让后台编辑不再只是单浏览器配置。

任务：

- 统一主后台、写实后台、房间配置和学习任务的项目 schema。第一版已完成，项目档案会写入 `projectSchema`。
- 写实后台补齐保存历史、草稿预览、本机发布、发布差异预览和演示页读取已发布版本。第一版已完成。
- 给项目档案增加 schema version、migration 和资产校验。迁移预检、执行记录和导入模型 SHA-256 校验第一版已完成。
- 给项目档案导入增加 localStorage JSON 字段级差异预览。第一版已完成，能显示新增、修改、删除字段路径。
- 给项目档案导入增加 localStorage JSON 字段级选择性恢复。第一版已完成，普通字段变化能恢复到 `sessions[0].score` 这类深层路径，结构变化保守回退到顶层字段。
- 给字段级恢复增加当前/档案值摘要和覆盖/新增/删除影响提示。第一版已完成。
- 给字段级恢复增加可展开 JSON 片段预览。第一版已完成，能对照当前本机和导入档案片段。
- 给项目档案导入模型仓库增加单模型差异预览。第一版已完成，能显示新增、修改和删除模型摘要。
- 给项目档案导入模型仓库增加单模型选择恢复。第一版已完成，能只恢复勾选的新增/修改模型或删除勾选的本机模型，未勾选模型保持不变。
- 给项目档案导入模型仓库增加单模型元数据片段对照。第一版已完成，能展开查看当前本机和导入档案的 key、名称、文件名、类型、大小、哈希和导入指标。
- 给项目档案导入模型仓库增加完整模型 JSON 安全预览。第一版已完成，能展开查看当前本机和导入档案的完整记录结构，二进制字段以摘要显示。
- 给项目档案导入模型仓库增加命名冲突处理。第一版已完成，能提示同名/同文件名不同 key 的模型，并可选择“保留本机自动改名”“替换本机同名模型”或自定义档案模型名称。
- 发布快照增加版本号、发布时间、发布说明、发布差异预览和回滚原因。主后台和写实后台第一版已完成。
- 明确远端适配接口：本机静态版继续可用，未来可替换为 API。

验收：

- 导出项目档案后，在新浏览器导入能恢复主场景、写实场景、房间配置和学习状态。
- 导出的 JSON 应包含 `projectSchema.kind: "mr-calligraphy-project-schema"`、`version: 1`、四类 section 摘要、导入模型资产清单和模型 SHA-256。
- 旧版本档案导入时会显示迁移说明。
- 导入档案预览时，学习状态、房间配置、场景布局等 JSON 项应显示字段级新增、修改、删除摘要，并能取消不想覆盖的字段；模型仓库应显示单模型差异、可展开元数据片段、完整模型 JSON 安全预览、命名冲突策略和自定义名称，并允许取消不想恢复的模型。
- 发布历史能区分草稿、已发布版本和回滚版本。

### 阶段 5：浏览器级验收

目标：减少“看起来能点，实际不可用”的回归。

任务：

- 引入 Playwright。第一版已完成工程配置和首批用例。
- 覆盖主场景不白屏、主后台保存后前台读取、书写后保存作品、导出报告、学习档案删除恢复。其中“前台书写后保存作品 / 导出报告”“主后台新增基础物体后发布到前台和发布差异预览”和“写实后台发布历史回滚与发布差异预览”第一版用例源码已完成。
- 对 WebGL 页面增加 canvas 非空像素检查。
- 对下载功能检查文件名和内容关键字段。

验收：

- 每次提交前能跑静态 smoke test。
- 高风险交互有浏览器级自动化覆盖。
- 失败时能定位到具体入口和控件。

当前限制：

- 本地 Codex 环境访问 npm registry 返回 `407 Proxy Authentication Required`，Playwright 依赖暂时无法安装；已用 `node --check` 和 smoke test 校验配置、用例语法，并继续保留 smoke test 作为提交前硬检查。
- 首批 E2E 源码已覆盖写实后台发布历史，但还没有覆盖模型导入、回收站恢复、移动端视口和 WebGL 非空像素。

## 7. 下一批建议开发顺序

1. 在具备 npm 代理认证的环境里安装 Playwright，跑通并扩展浏览器级验收。
2. 继续统一主后台与写实后台对象 schema、三方字段合并、完整 JSON 树和远端发布适配。
3. 增加原生 PDF 生成或服务端导出适配，把现有报告和报告对比离线 HTML 升级为更稳定的 PDF/云端长期报告产物。
4. 持续检查新增控件，禁止退回粗粒度 `real` 标注。

这批顺序的原则是：先让用户不会被假成功误导，再逐步补产品深度。
