# MR 书法康养舱真实应用开发执行清单

> 本清单用于长期开发管理。  
> 只要 Codex 或开发者完成一项并通过验收，就将 `- [ ]` 改为 `- [x]`。  
> 不允许把“页面能显示”“静态图能切换”“临时假数据能展示”当作完成。  
> 本清单以真实可用产品为目标，不再围绕 1-10 展示步骤开发。

---

## 勾选规则

1. 每个任务都有唯一编号。
2. 任务完成且通过验收后才可以勾选。
3. 部分完成不勾选，只在任务下方追加进度说明。
4. 每次提交应在 commit / PR 说明中写明完成的任务编号。
5. 如果新增任务，只能追加到对应阶段末尾，不修改旧编号含义。
6. 如果任务废弃，保留编号并注明废弃原因。
7. 任何“假功能”“固定报告”“静态切图”不得勾选为完成。

## MVP 完成标准

只有满足以下条件，才算第一版 MVP 完成：

- [ ] 舱内端和护工端分离运行。
- [ ] 护工端能启动真实 Session。
- [ ] Device Simulator 能控制舱门开关状态。
- [ ] 舱门状态影响 Session 流程。
- [ ] 老人端能完成一次书法体验。
- [ ] 系统能记录书写轨迹。
- [ ] 系统能生成作品。
- [ ] 系统能生成报告。
- [ ] 护工端能查看报告。
- [ ] 系统能进入清洁复位状态。
- [ ] 系统能恢复到下一位可用状态。

如果只是切换静态页面或播放固定效果图，不算完成。
